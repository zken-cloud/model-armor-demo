📖 Model Armor Demo Guide

🛡️ Model Armor Templates

The application provisions two templates in the us multi-region, each with a prompt and a response variant. Every filter starts at High and above on the latest filter model; after that, whatever you change in the editor stays.

Template Name Description
Image Redaction (Image Only) 🖼
modelarmor-demo-us-imgredact-prompt / -response		 Image input only, no caption. Advanced Sensitive Data Protection with an image de-identify template: every finding is boxed out of the picture and the redacted image is what the model receives. The reply shows the redacted image so you can see exactly what was removed. As the response template it does the same to images the model generates (pick the gemini-3.1-flash-image model): the generated picture is screened and redacted before it is shown.
Text & Image (Text Redaction Only) 🖼
modelarmor-demo-us-text-image-prompt / -response		 Text and image input. Ships with Advanced Sensitive Data Protection wired to your DLP inspect and text de-identify templates, so sensitive values in a text prompt are redacted before the model sees them (and again on the way back via the response variant). While that text de-identify is set, an uploaded image is blocked — open Edit and set SDP Mode to Basic (or clear De-identify) to screen images and captions instead. Switch it back for text redaction.

🌍 Location

Everything runs in the us multi-region. Image screening needs a multi-region, and Advanced SDP needs the DLP templates to live in the same location as the Model Armor template — Sensitive Data Protection has a us location but no eu one, so us is the only place both features work.

⚙️ Customization

Click Edit next to either template dropdown to change:

  • Responsible AI: Hate Speech, Dangerous Content, Harassment, Sexually Explicit. All default to High and above, so mild content deliberately passes. Lower a threshold to Low or Medium to see it trigger more readily.
  • Detection: Prompt Injection & Jailbreak, and Malicious URLs.
  • Sensitive Data Protection: Basic, or Advanced with inspect / de-identify templates. Those two fields are dropdowns listing the templates that exist in the selected region — hover one to see the infoTypes that trigger it.
    A de-identify template is either text or image, never both. Sensitive Data Protection de-identify configs use infoTypeTransformations (text) or imageTransformations (image), and these are mutually exclusive. Model Armor can only apply a text one to text and an image one to an image; the other kind of input makes it skip every filter, so the app blocks that request. Hence:
    • Inspect on its own screens both text and images, and reports findings such as a credit card number read out of a picture, without redacting.
    • A text de-identify template (e.g. AS-MA-DLP-DEID-US) redacts text prompts and model responses; put it on a text-only template.
    • An image de-identify template (e.g. AS-MA-DLP-DEID-US-IMG) boxes findings out of the picture; put it on an image-only prompt template and send images without a caption.
    • The image inspect template must not use a stored custom infoType — image redaction rejects it. That is why AS-MA-DLP-INS-US-IMG exists alongside AS-MA-DLP-INS-US.
    The dropdowns label each de-identify template [text] or [image].

Model Armor Filter Version is a dropdown at the top of the editor: the Latest alias (v3 today), the Stable alias (v1 today, moving to v3 on 25 Sep 2026), or a pinned v3 / v1. v1 retires on 29 Nov 2026. The version actually used is shown under the analysis panel after each request, so you can switch and compare detections live.

🖼️ Image Screening

Model Armor screens JPEG, PNG and BMP images up to 4 MB, reading them with both visual analysis and OCR. It does not read images embedded inside PDFs or Office documents.

⬇ Download the sample image

Attach it with the 📎 button and send. With Text & Image (Text Redaction Only) selected and its SDP Mode set to Basic, the memo trips four filters at once, all from text recognised inside the picture:

  • Jailbreak / PI — the "ignore all previous instructions" line
  • Sensitive Data — the credit card number
  • Responsible AI — harassment and dangerous content
  • Malicious URLs — the test malware link

A caption typed alongside an image is screened as a separate call, because Model Armor cannot accept text and an image in one request. Results are therefore labelled (image) and (text) so you can see which half tripped which filter.

Select Image Redaction instead and send the same image with no caption: the name, card number, email, phone number, IP address and SSN are boxed out in red, the reply shows that redacted picture, and the model only ever sees the redacted copy — ask it to read the card number and it cannot.

🚫 Blocking vs Observing

Turn Use default on and set a default response to see Model Armor block a violating prompt outright — the model is never called. Leave it off to watch the model respond anyway, which is useful for showing what unfiltered behaviour looks like. Note that the model sometimes declines a violating prompt by returning nothing at all; the app shows a placeholder rather than an empty bubble.

🔍 Analysis Panel

The panel on the right shows the result of every filter. Hover a card to see the detail behind it — matched categories and confidence, the infoTypes found, or the URLs matched.

  • ✔️ PASS — the filter ran and found nothing.
  • ❌ FAIL — the filter matched.
  • ⚠️ SKIPPED — the filter did not run, so the content was not checked. This is not a pass. It appears when Model Armor cannot process the input, or when an Advanced SDP template is missing or in the wrong location.

Use Show Raw Output for the full JSON returned by the API, including the OCR text extracted from an image.
